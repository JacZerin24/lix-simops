## On-demand full build workflow

GitHub Actions now contains **Full Endymion Case Build**.

It is intentionally an on-demand workflow because a complete build downloads multiple gigabytes and renders hundreds of images.

The workflow:

1. installs the data-processing stack
2. downloads the public source-case data needed for all products except LightningCast
3. validates the raw inventory
4. renders/builds the radar cache
5. renders/builds the meso cache
6. runs case-blindness/product validation
7. packages the resulting cache as a GitHub Actions artifact

Artifact name:

`endymion-case-cache-no-lightningcast`

The artifact contains:

- `data/cache/mardi-gras-dss-001/`
- raw inventory JSON
- build metadata

It deliberately does not contain the raw multi-gigabyte source archive.

## LightningCast remains a separate external processor step

The full public-data artifact is useful for:

- radar
- GOES visible/IR
- GLM flash density
- MRMS
- RAP environmental analysis
- observations

LightningCast is added after the external CSPP Geo step.

Recommended workflow:

1. download C02/C05/C13/C15 inputs locally with `prepare_endymion_case.py`
2. verify complete scans with `validate_lightningcast_inputs.py`
3. process with CSPP Geo LightningCast
4. stage imagery with `stage_lightningcast.py`
5. rerun the meso cache builder
6. validate with `validate_exercise_cache.py --require-lightningcast`

## Local-time display

V0.8 also carries each scenario's configured timezone into the participant session.

For Endymion, UI clocks, radar scan times, meso valid times, DSS messages, facilitator scheduled injects, and the exercise log display **America/Chicago** local simulation time instead of forcing participants to mentally convert UTC.

The server continues to store/transmit offset-aware timestamps internally.

## Rehearsal

See `docs/facilitator-rehearsal-runbook.md`.

## Exercise-integrity hardening

V0.8 also closes several issues that matter during a live displaced-real-time exercise:

- participant weather assets are served through the active session rather than by mounting the entire cache tree
- future radar/meso images are rejected until their mapped timestamp is at or before simulation time
- participant cache manifests omit historical source keys
- facilitator WebSocket control requires a random per-session access key in addition to the shared session code
- the simulation clock stops at the configured 4:30 PM CST exercise end
- the Vite development server proxies API/WebSocket traffic to the backend so participant computers can use the host workstation's LAN address without trying to connect to their own localhost
- strict raw-data validation checks the known public-archive counts for this source window, and final cache validation checks required product coverage plus referenced asset existence

The six-character session code is participant-facing. The facilitator access key should be shared only with additional facilitators.
