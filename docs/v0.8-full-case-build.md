# V0.8 — Full case build and rehearsal package

V0.8 treats the **May 12, 2021** source data as one complete Endymion
exercise package.

## Source window and build footprint

The source window is **06:00–07:45 UTC**. Because this case was changed after
the December 2022 build was validated, the May 2021 archive footprint should
be measured from the current branch with:

```bash
python scripts/estimate_case_download.py
```

Do not reuse the old December 2022 file-count or size estimates.

## On-demand full build workflow

GitHub Actions contains **Full Endymion Case Build**. The workflow is split
into independent radar, GOES IR, MRMS, and supporting-meso jobs so a single
hosted-runner interruption does not discard the entire build.

The workflow:

1. downloads May 12, 2021 source data
2. validates raw-data coverage
3. renders REF/VEL/CC/ZDR in parallel
4. renders GOES IR and each MRMS product independently
5. renders GLM, RAP MLCAPE, 0–1/0–3 km SRH, 0–3 km shear vectors, 0–6 km shear, and observations
6. assembles and validates the meso cache
7. merges radar and meso products
8. runs final case-blindness/product validation
9. publishes `endymion-case-cache-no-lightningcast` with 45-day retention

Participant timestamps are shifted by **+13 h 45 min** before being mapped to
February 6, 2027, placing the historical 2:05 AM tornado onset at about
3:50 PM exercise time.

## LightningCast

LightningCast remains a separate external CSPP Geo step. The full public-data
artifact contains the rest of the exercise products. To add LightningCast:

1. download C02/C05/C13/C15 L1b inputs
2. validate them with `validate_lightningcast_inputs.py`
3. process them with CSPP Geo LightningCast
4. stage the timestamped imagery
5. rebuild the meso cache
6. validate with `--require-lightningcast`

## Portable managed-Windows package

The **Build Portable Windows SimOps** workflow requires an explicit successful Full
Endymion Case Build run ID. It builds the React frontend in Actions and packages it with
FastAPI, the validated cache, and an offline Python 3.13 wheelhouse.

The portable runtime deliberately omits facilitator-only historical source-case metadata
and backend tests, and the packaging workflow scans participant-runtime text files for
historical source identifiers before publishing. The final portable artifact is retained
for 45 days.

## Rehearsal

See `docs/facilitator-rehearsal-runbook.md`.

A full rehearsal should use the built cache, three participant roles, the
mock Shift Log, and the Classroom participant links. Inject timing should be
tuned only after watching the actual May 2021 meteorological evolution at
1.5× playback.

## Exercise-integrity hardening

V0.8 also provides:

- session-gated participant weather assets
- no access to future radar/meso frames
- participant manifests without historical source keys
- per-session facilitator access keys
- a hard exercise end at 4:30 PM CST with a participant-visible completed state
- automatic client reconnect after ordinary transient WebSocket drops
- same-origin API/WebSocket traffic for portable/LAN operation
- strict raw-data and final-cache validation, including radar start/end coverage and no post-exercise frames
