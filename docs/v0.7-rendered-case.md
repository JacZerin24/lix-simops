# V0.7 — Rendered Endymion case package

V0.7 turns the raw December 14, 2022 source-case files into participant-facing products that can be replayed on the February 6, 2027 Endymion simulation clock.

## Important source-data decision

The original plan preferred SPC mesoanalysis archive imagery for MLCAPE, effective bulk shear, and 0–1 km SRH.

A third-party SPC archive explorer that has mapped historical product availability notes that **no SPC mesoanalysis images were archived from the end of November 2022 through most of December 2022**. Because our source case is December 14, the exercise should not depend on those images being recoverable.

V0.7 therefore uses the official NOAA RAP archive for the environment tab:

- RAP 90-mb mixed-layer CAPE
- RAP 0–6 km bulk shear
- RAP 0–1 km storm-relative helicity

These are explicitly labeled as RAP products in the participant interface. We are not presenting the 0–6 km shear field as effective bulk shear.

SPC still remains a useful reference when archived products exist, but it is no longer a blocking dependency for this case.


## Render locally reproducible meso products

```bash
python scripts/build_endymion_meso_inputs.py
```

This produces:

- GOES-16 visible
- GOES-16 infrared
- five-minute GLM flash-density images
- MRMS MESH
- MRMS 0–2 km azimuthal shear
- MRMS precipitation rate
- MRMS lowest-altitude reflectivity
- RAP MLCAPE
- RAP 0–6 km bulk shear
- RAP 0–1 km SRH
- surface observation maps

The final step of that script runs `build_meso_cache.py` and remaps source local times onto February 6, 2027.

## GLM terminology

The built-in GLM renderer grids **flash centroids** from LCFA files into five-minute density maps.

That is intentionally labeled **GLM Flash Density**.

It is **not** true Flash Extent Density (FED). If the exercise team later runs the CSPP Geo Gridded GLM software, a true FED product can be added as a separate product without mislabeling the fallback display.

## LightningCast

LightningCast is the one V0.7 product that cannot be produced solely by this repository because CSPP Geo LightningCast is distributed through the SSEC registered-user download system.

The repository does everything around that external processor:

1. downloads GOES-16 ABI L1b C02/C05/C13/C15
2. validates that complete four-channel scans exist
3. provides the expected New Orleans/LIX exercise domain
4. stages timestamped CSPP imagery
5. incorporates those images into the normal time-remapped SimOps manifest

Validate input completeness:

```bash
python scripts/validate_lightningcast_inputs.py
```

After running CSPP Geo LightningCast externally, stage its images:

```bash
python scripts/stage_lightningcast.py --input /path/to/cspp/output
```

Then rebuild the meso cache.

## Full case build

Once raw data and LightningCast (if available) are staged:

```bash
python scripts/build_endymion_case.py
```

To require LightningCast before declaring the case complete:

```bash
python scripts/build_endymion_case.py --require-lightningcast
```

## Case-blindness protection

V0.7 closes an important source-date leak.

Historical `source_key` values remain in server-side manifests for facilitator traceability, but they are **no longer returned by the Radar or Meso participant APIs**.

The final validator also checks that:

- participant timestamps are mapped to 2027
- participant asset filenames do not contain `20221214`
- required radar/meso products contain frames

Run:

```bash
python scripts/validate_exercise_cache.py --require-lightningcast
```

before the final rehearsal.
